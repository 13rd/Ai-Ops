================================================================================
 SERVER MONITOR — Инструкция по развёртыванию и запуску
 Система обнаружения аномалий и рекомендаций для серверной инфраструктуры
================================================================================

Архив содержит исходный код проекта (backend + frontend), обученные ML-модели
и конфигурацию для развёртывания. Файлы документации (*.md), виртуальные
окружения, node_modules, база данных и кэши в архив НЕ включены — они
создаются при установке.

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

  alembic/, alembic.ini Миграции БД
  ml/                   Тренировочные скрипты ML-моделей
  data_gen/             Генерация данных и тестовые стенды (Docker testbeds)

--------------------------------------------------------------------------------
 1. ТРЕБОВАНИЯ
--------------------------------------------------------------------------------
  Вариант A (Docker — рекомендуется):
    - Docker 24+ и Docker Compose v2
  Вариант B (вручную):
    - Python 3.11
    - uv (менеджер пакетов):  pip install uv   (или https://docs.astral.sh/uv/)
    - Node.js 20+ и npm       (для пересборки frontend; в архиве уже есть dist/)
    - PostgreSQL 15 + Redis 7 (или используйте SQLite для разработки)
    - (опционально) Ollama + модель qwen2.5:3b — для LLM-рекомендаций

--------------------------------------------------------------------------------
 2. НАСТРОЙКА ОКРУЖЕНИЯ (обязательно)
--------------------------------------------------------------------------------
  1) Скопируйте шаблон и создайте свой .env:
        cp .env.example .env

  2) Сгенерируйте и пропишите СЕКРЕТЫ (не оставляйте значения по умолчанию!):
        # SECRET_KEY (JWT):
        python -c "import secrets; print(secrets.token_urlsafe(48))"
        # SSH_ENCRYPTION_KEY (Fernet, шифрование SSH-ключей в БД):
        python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

     Впишите их в .env в поля SECRET_KEY и SSH_ENCRYPTION_KEY.
     Также задайте надёжный DB_PASSWORD.

  3) Прочие параметры (.env): DATABASE_URL, REDIS_URL, OLLAMA_BASE_URL/MODEL,
     TELEGRAM_BOT_TOKEN (если нужны уведомления) — см. комментарии в .env.example.

--------------------------------------------------------------------------------
 3. ВАРИАНТ A — ЗАПУСК ЧЕРЕЗ DOCKER COMPOSE (рекомендуется)
--------------------------------------------------------------------------------
  Поднимает: PostgreSQL, Redis, backend (с авто-миграцией и сидом БД),
  nginx (раздаёт frontend), Ollama (+ авто-загрузка модели qwen2.5:3b),
  stress-target (демо-контейнер источника аномалий).

  1) Убедитесь, что .env заполнен (см. п.2).
  2) Соберите и запустите:
        docker compose up -d --build
  3) Дождитесь готовности (healthcheck backend ~40с):
        docker compose ps
        docker compose logs -f backend
  4) Откройте:
        Frontend:        http://<сервер>/           (nginx, порт 80)
        API:             http://<сервер>:8000/
        Swagger/OpenAPI: http://<сервер>:8000/docs
        Health:          http://<сервер>:8000/health

  Остановка:           docker compose down
  Полная очистка (вкл. данные БД):  docker compose down -v

  ПРИМЕЧАНИЕ по LLM: первый запуск Ollama скачивает модель qwen2.5:3b
  (несколько минут). До завершения загрузки рекомендации работают в
  fallback-режиме по шаблонам.

--------------------------------------------------------------------------------
 4. ВАРИАНТ B — РУЧНОЙ ЗАПУСК (без Docker)
--------------------------------------------------------------------------------
  BACKEND
  -------
  1) Установка зависимостей:
        uv sync
  2) Применить миграции:
        uv run alembic upgrade head
  3) Создать пользователей по умолчанию:
        uv run python scripts/seed_db.py
  4) Запустить API:
        uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2
     (для разработки:  make run   — с авто-перезагрузкой)

  Для разработки без PostgreSQL можно использовать SQLite, указав в .env:
        DATABASE_URL=sqlite+aiosqlite:///./server_monitor.db

  FRONTEND
  --------
  В архиве уже есть собранный frontend/dist/ — его можно сразу раздавать
  любым статическим сервером или nginx (см. nginx.conf).

  Пересборка при необходимости:
        cd frontend
        npm install
        npm run build            # результат в frontend/dist/
  Dev-режим:
        npm run dev              # http://localhost:5173

  Раздача dist/ через nginx — используйте приложенный nginx.conf
  (он раздаёт статику и проксирует /api на backend:8000).

  Health endpoint:      curl http://localhost:8000/health

--------------------------------------------------------------------------------
 8. ЧАСТЫЕ ПРОБЛЕМЫ
--------------------------------------------------------------------------------
  - 500 при логине / "network error": backend не поднялся или неверный
    DATABASE_URL. Проверьте `docker compose logs backend`.
  - Рекомендации без LLM (только шаблоны): Ollama ещё не скачал модель или
    недоступен по OLLAMA_BASE_URL. Проверьте `docker compose logs ollama-init`.
  - Порт 80/8000/5432 занят: измените проброс портов в docker-compose.yml.
  - SSH-функции не работают: не задан/сменён SSH_ENCRYPTION_KEY (Fernet) —
    ключи в БД зашифрованы прежним ключом; нужен исходный ключ.
