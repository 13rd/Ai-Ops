# 05 — ML Models

Status: implemented (Sprint 3). Pipeline = LSTM Autoencoder (anomaly detection) → CNN-LSTM classifier (type) → SHAP+MSE explainer → Ollama recommender.

## 1. Overview

| Component | Task | Input | Output |
|---|---|---|---|
| LSTM Autoencoder | Anomaly detection | 60×10 metric window | Reconstruction MSE |
| CNN-LSTM Classifier | Anomaly type (7 classes) | 60×10 window | softmax(7) |
| SHAP DeepExplainer + per-feature MSE | Explainability | window, X_hat, class_idx | Ranked feature impacts |
| Ollama `qwen2.5:3b` | Remediation recommendation | type + top features | (explanation, command) |

Fallbacks:
- Registry has no models → rule-based detector (legacy)
- SHAP init fails → MSE-only explanation
- Ollama timeout/error/unsafe output → deterministic template

## 2. Data

- **Source:** `tmp/ready/clean_dataset.jsonl` (synthetic, generated by `data_gen/scripts/generate_clean_dataset.py`)
- **Volume:** 34,560 rows = 6 servers × 24 h × 240 rows/h (15-second cadence)
- **Class mix:** ~70% normal, ~5% per anomaly type, ground-truth label per row
- **Ingest:** `scripts/import_labeled_jsonl.py` → `metric_snapshots` + `anomaly_events`; idempotent on `(server_id, collected_at)`; persists `containers_running_ratio` and `swap_used_mb` in `MetricSnapshot.extra_data`

### 2.1 Ten features

`ml/config.py::FEATURE_COLS` (also rebuilt at inference from `extra_data`):

1. `cpu_percent`
2. `load_avg_1m`
3. `mem_percent`
4. `swap_used_mb`
5. `disk_percent`
6. `disk_read_bps` — rate from byte counter / 15 s
7. `disk_write_bps`
8. `net_in_bps`
9. `net_out_bps`
10. `containers_running_ratio` — running containers / total

### 2.2 Seven classes

`normal, cpu_spike, memory_leak, disk_fill, network_storm, container_crash, service_down`

## 3. Windowing & Splits

| Param | Value |
|---|---|
| Window size | 60 steps (15 min @ 15 s) |
| Train stride | 2 (dense sampling) |
| Val/test stride | 4 (matches inference cadence = 1 / min) |
| Majority label ratio | 0.25 — window inherits anomaly label when ≥15 of 60 samples share one type |

Splits are per-server, chronological: 60% train, 20% val, 20% test. Per-server `StandardScaler` is fit on TRAIN-normal rows only and persisted at `models/scalers/{server_name}.pkl`.

## 4. Architectures

### 4.1 LSTM Autoencoder (`ml/models/lstm_autoencoder.py`)

```
Input (60, 10)
→ LSTM(32, return_sequences=True)
→ LSTM(16)                          # latent
→ RepeatVector(60)
→ LSTM(16, return_sequences=True)
→ LSTM(32, return_sequences=True)
→ TimeDistributed(Dense(10))
Output (60, 10)
```

Loss MSE, Adam(1e-3), batch=64, epochs ≤150 with EarlyStopping(patience=10).

### 4.2 CNN-LSTM Classifier (`ml/models/cnn_lstm_classifier.py`)

```
Input (60, 10)
→ Conv1D(32, k=5, relu) → MaxPool1D(2)
→ Conv1D(64, k=3, relu) → MaxPool1D(2)
→ LSTM(32) → Dropout(0.3)
→ Dense(32, relu) → Dropout(0.3)
→ Dense(7, softmax)
```

Loss sparse_categorical_crossentropy, balanced class weights, batch=32, epochs ≤200, EarlyStopping on val_accuracy (patience=15).

## 5. Threshold Calibration

`ml/train/calibrate_threshold.py`:
- Run AE on val-normal windows → array of MSE values
- Threshold = 80th percentile of that distribution (heavy-tailed normals; balances precision/recall)
- Persist `models/threshold.json` (`threshold`, `mean`, `std`, `p90`, `p95`)
- Sample 100 val-normal windows → `models/background.npy` (SHAP background)

## 6. Inference Pipeline

`MLPipeline.analyze(db, server)`:

1. Registry has models? else rule-based fallback
2. Fetch last 60 `MetricSnapshot` for the server (chronological)
3. Load `scalers/{server.name}.pkl`; abort if missing
4. Extract 10-feature matrix, scale, reshape → (1, 60, 10)
5. `recon = AE.predict(X)`; `err = mean((X - recon)²)`
6. `err ≤ threshold` → return (normal)
7. Severity from z-score `(err − threshold_mean) / threshold_std`: <1 low, <2 medium, <3 high, ≥3 critical
8. `probs = classifier.predict(X)` → argmax → label (skip if `normal`)
9. Explainer: SHAP DeepExplainer over background (50% weight) + per-feature MSE (50%) → sorted impacts
10. Dedup: skip if open `Anomaly` of same type already exists for the server
11. Persist `Anomaly` row (severity, score, threshold, shap_explanation, metrics_snapshot)
12. Recommender: Ollama (`qwen2.5:3b`, 10 s timeout) with safety filter; fallback to template
13. Persist `Recommendation`, dispatch notifications

Inference cadence: every `ML_INFERENCE_INTERVAL_SEC` (default 60 s) via `MLAnalysisJob` (started in FastAPI lifespan alongside `CollectorScheduler`).

## 7. Recommender Safety

`app/services/ml/recommender.py::is_command_safe(cmd)` blocks (regex deny-list, lowercased input):
- `rm -rf …`
- `dd if=…`, `mkfs…`
- fork bomb `:(){:|:&};:`
- `shutdown`, `reboot`, `halt`, `poweroff`
- `chmod 777 /…`, `chown … /…`
- `nc … | sh`, `curl|sh`, `wget|sh`
- `> /dev/sd*`, `> /etc/…`

Unsafe / empty Ollama output → deterministic template per anomaly type.

## 10. Training Workflow

```bash
# 1. Generate clean labeled data (~34k rows, 6 servers × 24h)
uv run python -m data_gen.scripts.generate_clean_dataset --servers 6 --hours 24

# 2. Apply DB migrations
uv run alembic upgrade head

# 3. Ingest into DB
uv run python -m scripts.import_labeled_jsonl tmp/ready/clean_dataset.jsonl

# 4. Build per-server splits + scalers
uv run python -m ml.train.prepare_dataset --out data/processed

# 5. Train LSTM AE
uv run python -m ml.train.train_lstm_ae --epochs 150

# 6. Calibrate threshold + dump SHAP background
uv run python -m ml.train.calibrate_threshold

# 7. Train CNN-LSTM classifier
uv run python -m ml.train.train_classifier --epochs 200

# 8. Evaluate against spec targets
uv run python -m ml.train.evaluate
cat models/eval_report.json
```

## 11. Configuration

`app/core/config.py` (override via env / `.env`):

| Key | Default | Purpose |
|---|---|---|
| `ML_MODELS_DIR` | `models` | Directory of `.keras` + `threshold.json` + `scalers/` |
| `ML_INFERENCE_INTERVAL_SEC` | `60` | `MLAnalysisJob` loop period |
| `ML_WINDOW_SIZE` | `60` | Sliding window length |
| `ML_BACKGROUND_SET_SIZE` | `100` | SHAP background sample count |
| `OLLAMA_BASE_URL` | `http://ollama:11434` | Ollama HTTP endpoint |
| `OLLAMA_MODEL` | `qwen2.5:3b` | Model used by Recommender |
| `OLLAMA_TIMEOUT_SEC` | `10` | Per-request timeout |

## 12. Known Risks

- **DeepExplainer compatibility:** SHAP 0.45 on Keras 3 / TF 2.16 may fall back to MSE-only (logged warning). Explanations remain usable from AE side.
- **Unknown server at inference:** no scaler → detector returns `None`. Future: online StandardScaler bootstrap after first N samples.
- **Ollama cold start:** first request after container startup may exceed 10 s → one template fallback.
